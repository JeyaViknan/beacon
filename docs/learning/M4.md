# M4 — Terraform, build and secrets scripts

**Built:** `infra/bootstrap` (S3 state bucket, GitHub OIDC provider, deploy role, $1 budget), `infra/modules/probe` (Lambda + 1-minute schedule per region), `infra/main` (DynamoDB, SQS + DLQ, two SNS topics, five Lambdas with least-privilege roles, Function URLs, CloudFront + S3 with OAC, SSM parameters, 9 alarms, ops dashboard), and the scripts that build zips, set secrets, generate VAPID keys and seed the demo product.

**Why this design:**
- **State:** S3 backend with `use_lockfile = true` (native S3 locking since Terraform 1.10), so no DynamoDB lock table. The bootstrap stack keeps local state because it creates that bucket.
- **CI auth:** GitHub OIDC → `beacon-github-deploy` role, trusted only for `repo:JeyaViknan/beacon:environment:production`, so no long-lived keys exist anywhere.
- **Least privilege:** one IAM role per Lambda. The probe can only `GetItem` the `CONFIG` partition and `SendMessage` to one queue.
- **Reproducible zips:** pinned deps, aarch64 manylinux wheels, fixed timestamps → identical hash → Terraform only redeploys what changed.
- **Secrets order:** Terraform writes placeholders with `ignore_changes`; `put_secrets.sh` overwrites them afterwards, so real values never enter state or Git.
- **No dependency cycle:** the app URL is an SSM parameter read at runtime, not a Lambda env var (CloudFront depends on the API's Function URL).
- **Provider 6.x (ADR 0012):** needed for the post-Oct-2025 Function URL permission (`invoked_via_function_url`).

**Interview questions**
1. *How does GitHub deploy without AWS keys?* OIDC: GitHub signs a short-lived JWT, and STS exchanges it for role credentials if the token's `sub` matches the trust policy (repo + environment).
2. *How is Terraform state protected?* A private, versioned, encrypted S3 bucket with a TLS-only policy and S3 native locking; old versions expire after 90 days.
3. *Why `ignore_changes` on SSM values?* Terraform owns the parameter's existence, humans own its value, and secrets stay out of state.
4. *How do you add a probe region?* Add it to `probe_regions`; its module's `count` flips to 1 using that region's provider alias.
5. *How do you stay inside the free tier?* Provisioned DynamoDB 20/20 of 25/25, 10 alarm metrics, 7-day logs, no NAT/ALB/API Gateway, plus a $1 budget alert.
